# 禁用全部展示功能 —— 实现方案

> 需求来源：`docs/禁用全部展示功能`。本文是修订后的落地方案（采用「半后端」：订阅存储+限额放后端，过滤/渲染放前端）。

## 目标

非 admin/manager 用户不再拥有全局视图，只能通过「订阅星系（1 个或多个）」看到订阅星系族（订阅星系 + 与之连通的所有星系/连线）。admin/manager 保留全局视图。

## 可见性规则（Option A，已确认）

```
可见星系 = BFS(订阅星系 ∪ 我角色当前所在星系)
```

- 订阅星系始终在画布上展示，且作为 BFS 根。
- 我角色当前所在星系（`characters[].location.solar_system_id` 且 `eve_id ∈ userCharacters`）也作为 BFS 根——这样自己角色跑到订阅簇外（例如 C→D→E，当前在 E）时，C/D/E 因连通会一并可见。
- **锁定（locked）星系在订阅视图下失效**，仅全局视图保留 locked 语义。
- 不做「角色访问历史」（`get_character_jumps` 是死代码，角色模型也只存当前位置）。

## 角色权限与限额

| 角色 | 全局视图 | 订阅限额 |
|---|---|---|
| admin / manager（`admin_map` 或 `manage_map`） | ✅ | 不限（空 = 全局） |
| member | ❌ | ≤ 3 |
| viewer | ❌ | ≤ 1 |

## 分阶段改动

### Phase 0 — 数据模型 & 注释

- `MapUserSettings`（`lib/wanderer_app/api/map_user_settings.ex`）新增 `subscribed_system_ids : {:array, :string}`，仿照已有 `hubs` 字段：
  - 属性 + `update_subscriptions` action + `define(:update_subscriptions, ...)`。
  - 数据库迁移：给 `map_user_settings_v1` 加 `subscribed_system_ids` 列。
- 修复 `map_system.ex` 中 `status` 注释 `home: 8` → `home: 1`（与实际代码、前端 `STATUSES.home=1` 一致）。

### Phase 1 — 订阅 CRUD + 限额（后端）

- 新增 UI 事件 `update_subscriptions`（body: `{"system_ids" => [...]}`）：
  - 校验限额：member ≤ 3、viewer ≤ 1、admin/manager 不限。
  - 写入 `MapUserSettings.subscribed_system_ids`。
  - 广播 `map_updated` 带 `subscribed_system_ids`。
- `init`（`get_map_data` / `map_start`）与 `map_updated` 的载荷中注入 `subscribed_system_ids` 与 `subscription_limit`，前端据此渲染。
- 复用现有 `user_permissions`（`admin_map` / `manage_map`）判断角色。

### Phase 2 — 前端过滤改造

- `MapRootData` 新增：`subscribedSystemIds: string[]`、`subscriptionLimit: number | null`。
- `useFilteredMapData`：BFS 种子改为 `订阅星系 ∪ 我角色当前所在星系`；订阅视图下 `effectiveLockedIds` 置空；全局视图保留 locked。
- `useViewLayout` / `computeBfsLayout`：支持多根布局；「Re-arrange layout」重排基于订阅族。
- `ViewModeSelector` → 改为「订阅管理」：
  - 输入星系代码添加/删除订阅，展示限额。
  - admin/manager 额外保留「全局视图」开关。
  - member/viewer 无订阅时显示引导（输入星系代码）。
- 右键菜单「Re-arrange layout」：`status === home` **或** 订阅星系都显示。
- `TopSearch`：无需改（订阅视图下 `systems` 已收敛）。

## 风险 / 待确认

- 本方案不防「开 devtools / 调接口枚举」的技术型 spy（已确认暂不考虑）。
- 「我角色当前所在星系」依赖前端 `characters[].location.solar_system_id` 与 `userCharacters`，已核实存在。
