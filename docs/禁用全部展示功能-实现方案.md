# 禁用全部展示功能 —— 实现方案

> 需求来源：`docs/禁用全部展示功能`。采用「半后端」：订阅存储 + 限额 + 手动添加清单放后端，过滤/渲染放前端（不防 devtools/接口枚举的技术型 spy，已确认暂不考虑）。

## 目标

非 admin/manager 用户不再拥有全局视图，只能通过「订阅星系（1 个或多个）」看到订阅星系族。admin/manager 保留全局视图。

## 可见性规则

订阅视图（`viewMode === 'home'`）下：

```
可见星系 = BFS(订阅星系 ∪ 我角色当前所在星系) ∪ (孤立星系 ∩ 我手动添加的星系)
```

- 订阅星系 + 我角色当前所在星系作为 BFS 根。
- **首次订阅前不渲染任何星系**（`subscribedSystemIds` 为空 → 空视图）。
- **孤立星系（无连线）只在我手动添加清单（`manually_added_system_ids`）里时才可见**，便于手动右键添加后立即看到并接线；别人的孤立星系不可见。
- 全局视图（`viewMode === 'all'`）返回全量。

## 锁定（locked）语义

| 维度 | 全局视图 | 订阅视图 |
| --- | --- | --- |
| 过滤（始终可见 + BFS 桥） | ✅ 生效 | ❌ 失效 |
| 拖动（draggable） | ❌ 锁定不可拖 | ✅ 锁定可拖（只改本地布局，不写后端） |
| 删除（deletable） | ❌ 锁定不可删 | ❌ 锁定不可删 |

说明：订阅视图下拖动是本地布局（`savePosition` 写 localStorage），不影响全局坐标，故可放开；删除是全局操作，锁定仍不可删。

## 角色权限与限额

| 角色 | 默认视图 | 全局视图 | 订阅限额 |
| --- | --- | --- | --- |
| admin / manager（`admin_map` 或 `manage_map`） | 全局（`all`） | ✅ 可切换 | 不限 |
| member | 订阅（`home`） | ❌ | ≤ 3 |
| viewer | 订阅（`home`） | ❌ | ≤ 1 |

视图模式默认值由角色决定，不再读 localStorage。

## 数据模型

`MapUserSettings`（`map_id + user_id` 每用户一条，已有 `hubs`/`settings`）新增两个数组字段：

- `subscribed_system_ids`：订阅星系 id（string）。
- `manually_added_system_ids`：手动右键添加的星系 id（string），仅 `manual_add_system` 追加，**粘贴不算**，**不清理**（过期 id 被过滤时自然忽略）。

迁移：
- `20260816000000_add_map_user_settings_subscribed_systems.exs`
- `20260817000000_add_map_user_settings_manually_added_systems.exs`

## 已实现改动

### 后端

- `update_subscriptions` UI 事件：限额校验（member≤3 / viewer≤1 / admin+manager 不限）→ 写 `subscribed_system_ids` → **自动把订阅星系加入地图**（`add_system`，幂等）→ 回推 `map_updated`。
- `manual_add_system`：`add_system` 后追加 `manually_added_system_ids` → 回推 `map_updated`，使刚加的星系立即可见。
- `init` 载荷注入：`subscribed_system_ids`、`manually_added_system_ids`、`subscription_limit`。
- `map_system.ex` 注释修正（home 应为 1）。
- 容器启动自动迁移：`rel/docker-entrypoint.sh` 启动前执行 `migrate.sh`（`interweave_migrate`）。

### 前端

- `MapRootData` 新增：`subscribedSystemIds`、`manuallyAddedSystemIds`、`subscriptionLimit`。
- `computeVisibleSystemIds`（纯函数，`useFilteredMapData.ts`）：按上述可见性规则计算；`MapRootProvider` 计算并暴露 `visibleSystemIds` 到 context。
- `ViewModeSelector` → 订阅管理（搜索订阅/删除/限额显示，admin 保留全局开关）。
- `TopSearch` 搜索列表按 `visibleSystemIds` 过滤，跟随订阅视图。
- `useViewLayout` / `computeMultiBfsLayout`：多根布局，根只用订阅星系（角色星系作为子节点或回退数据坐标）。
- 锁定星系在订阅视图可拖动：`Map.tsx` `displayNodes` 覆盖 `draggable`。
- `useMapInit`（context）：非 admin/manager 在 init 时同步钳制 `viewMode = 'home'`，避免全局视图闪现。
- `useMapInit`（reactflow）：单次 `setNodes` 内直接应用布局，避免先落数据坐标再跳回。

## 已知边界 / 说明

- 本地 dev 需先 `make migrate` 再 `make start`；前端改动需先 `make deploy`（重建资产）再 `make start`。
- 路线计算报 `scheme is required for url: /route/multiple`：`CUSTOM_ROUTE_BASE_URL` 环境变量未配置（独立 route builder 服务的地址），与订阅功能无关，待配置或加静默降级。
